# 카페 판매·손익·재고 관리 제품 요구사항 문서

- 작성일: 2026-10-12
- 상태: PRD의 기능 범위와 권고 방향 확정. D01은 사용자 선택 A, 나머지는 2026-10-12 사용자 지시 “모두 추천으로 해줘”를 반영했다. 계산식·화면 디자인·기술·상세 동작과 구체적인 운영 값은 후속 설계 사항이다.
- PRD: 어떤 문제를 해결하고 어떤 기능을 만들지 정리하는 제품 요구사항 문서.
- MVP: 처음부터 모든 기능을 만들기보다, 핵심 일을 끝까지 할 수 있게 만드는 첫 버전.

## 1. 목적과 핵심 흐름

카페 운영자가 판매와 비용을 직접 관리하고, 어떤 메뉴가 수익에 도움이 되는지와 매장의 손익, 재료 잔량을 확인한다. 이후 예상 손익과 필요한 발주량까지 확장한다.

**판매 기록 입력 → 메뉴별 수익성 확인 → 같은 기간의 손익 확인 → 해당 판매가 반영된 재료 잔량 확인**을 첫 버전의 핵심 흐름으로 삼는다. 판매를 수정하거나 삭제해도 관련 결과가 서로 맞아야 한다.

사용 대상은 카페 운영자다. 1차는 매장 한 곳, 운영자 한 명, 한 기기에서 사용하는 범위로 정한다. 직원별 권한, 여러 매장, 여러 기기의 동시 사용은 1차에 포함하지 않는다.

## 2. 자료에서 확인한 사실

### 2.1 검토한 자료와 검토 범위

- `../data/데이터설명.md`: 출처, 기간, 단위, 중복 관계와 해석 주의사항을 확인했다.
- `../data/매장운영데이터.xlsx`: 모든 시트의 기록 수와 열, 주요 기록 전체를 읽었다.
- `../data/매장운영데이터.json`: 전체 기록, `meta`, `settings`를 확인했다.
- 엑셀과 JSON의 아래 11개 업무 기록 묶음은 날짜·월 표기와 빈칸 표현을 맞추어 대조했으며, 기록 수와 값이 일치했다. 별도로 엑셀에는 안내 시트와 자료정보 시트가 있다.
- 판매ID, 비용ID, 재고 기록ID의 중복은 없었다. 날짜·메뉴·판매채널 조합의 판매 중복도 없었다. 이는 제공된 자료에 대한 확인이며, 앞으로 가져오는 파일의 품질을 보장하지 않는다.

### 2.2 어떤 기록이 있는가

| 기록 | 건수 | 확인한 내용 | 기획에 쓰이는 곳 |
| --- | ---: | --- | --- |
| 공급사 | 3 | 공급사ID, 이름 | 재료의 공급처 참고 |
| 재료 | 11 | g·ml·개 단위, 구매용량, 최초가격, 공급사, 납기·안전재고 영업일 | 재료 잔량과 향후 발주 참고 |
| 메뉴 | 8 | 이름, 판매기준가, 음료·디저트 분류, 레시피버전 | 판매 대상과 메뉴별 결과 |
| 레시피 | 22 | 메뉴 한 개의 재료 사용량, 적용채널 | 판매와 재료 사용의 연결 |
| 재료가격이력 | 33 | 적용시작일별 구매가격과 구매용량 | 시점에 따른 원가 정보 |
| 영업달력 | 457 | 날짜, 영업·마감 여부, 날씨, 메모 | 기록 완료 기간과 미완료 기간 구분 |
| 판매기록 | 6,112 | 날짜, 메뉴, 매장·포장 채널, 수량, 당시 단가, 할인, 순매출, 수수료, 당시 개당 원가 | 메뉴 수익성과 기간 실적 |
| 초기재고 | 11 | 2025-07-01 영업 시작 전 수량 | 재료 잔량의 출발점 |
| 재고기록 | 1,515 | 입고 1,302건, 폐기 189건, 실사조정 24건 | 판매 외 재료 변동과 실측 확인 |
| 월비용계획 | 120 | 월별 8개 비용항목과 금액 | 향후 비용 계획 참고 |
| 비용기록 | 3,560 | 날짜별 비용항목, 금액, 배분기준 | 기간별 손익 |

비용항목은 임차료, 관리비, 인건비, 사업주 부담 보험료, 수도광열비, 통신·소프트웨어, 광고비, 소모품·청소비다. 현재 레시피에는 R1 버전이 있다. 포장 판매에만 쓰이는 포장재가 포함된다.

### 2.3 출처와 기간

- 프렙 카페를 가정해 직접 구성한 가상 샘플이다. 실제 매장 실적이나 미래 예측의 정확성을 입증하는 자료가 아니다.
- 판매·비용 기록은 2025-07-01부터 2026-09-18 마감까지다.
- 재고 변동 기록은 2025-07-02부터 2026-09-18까지이며, 그 전에 초기재고가 있다.
- 영업달력은 2026-09-30까지 있다. 9월 19일부터 30일까지 12일은 마감되지 않았다.
- 금액은 원, 부가세 제외 기준이다. 재료별 수량 단위는 g·ml·개다.
- 엑셀 자료정보는 10행이고 JSON의 `meta`에 출처·기간 등이 있다. JSON의 `settings`는 비어 있다. 제품의 판단 기준이 이미 정해져 있다는 뜻으로 해석하지 않는다.

## 3. 기획할 때 주의할 점

| 자료의 사실 또는 한계 | 제품 요구사항에 미치는 영향 |
| --- | --- |
| 엑셀과 JSON은 같은 자료다. | 두 형식을 별도 실적으로 합치지 않는다. 초기 자료는 한 형식으로 한 번만 반영한다. |
| 판매 한 행은 날짜·메뉴·채널별 집계다. | 6,112건을 주문 6,112건이나 고객 6,112명으로 설명하지 않는다. |
| 월비용계획과 비용기록은 같은 비용의 월·일 표현이다. | 1차 실제 기간 손익에는 비용기록을 사용한다. 월비용계획은 계획 참고로 구분하며 같은 지출로 중복 포함하지 않는다. |
| 비용기록은 월 비용을 날짜별로 나눈 기록이다. | 비용 날짜를 실제 결제일이나 현금이 빠져나간 날짜로 단정하지 않는다. 손익과 현금 잔액을 구분한다. |
| 판매 당시 단가·할인·수수료·개당 원가가 남아 있다. | 현재 메뉴 가격이나 재료 가격으로 과거 기록을 임의로 바꾸지 않는다. 수정할 때의 처리 기준은 미정이다. |
| 구매가격은 구매용량 전체의 가격이다. | 예를 들어 우유 한 묶음의 가격과 라떼 한 잔에 든 우유 비용을 혼동하지 않는다. |
| 포장재 레시피는 포장 채널에만 적용된다. | 같은 메뉴라도 매장 판매와 포장 판매의 재료 사용과 수익성 차이를 보존한다. |
| 입고는 양수, 폐기는 음수이고 실사조정은 양쪽 모두 가능하다. | 실제 센 수량과 증가·감소 수량을 같은 뜻으로 취급하지 않는다. |
| 재고에 실측수량이 일부 포함된다. | 실제 센 수량을 해당 기준 시점의 재고 기준으로 삼는다. 실측과 조정량은 구분한다. 과거 판매 수정과 실사 기록의 관계 등 상세 반영 방식은 후속 설계에서 정한다. |
| 미래 영업달력은 판매 완료 기록이 아니다. | 미마감 날짜를 매출 0인 날로 간주하지 않는다. |
| 2025년과 2026년은 일부 기간만 있다. | 연간 결과를 완전한 1년 실적으로 설명하지 않고 실제 포함 기간을 알린다. |
| 빈칸은 해당 없음 또는 미입력이다. | 빈칸을 일괄적으로 0으로 바꾸지 않는다. 부족한 정보가 있는 결과를 확정값처럼 제공하지 않는다. |
| 납기와 안전재고 일수는 영업일 기준이다. | 향후 발주 참고 기능에서 휴무와 영업일을 구분해야 한다. |

파일에 있는 과거 원가·수수료·배분 값은 기존 기록이다. 그것만으로 앞으로의 수익성 분류, 전망 방식, 비용 배분, 재고 정책을 합의했다고 볼 수 없다.

## 4. 요청된 전체 기능과 확정한 구현 단계

아래 단계 구분은 4시간 제한을 고려한 추천안에 대해 사용자가 일괄 채택한 범위다. 2차 기능도 전체 제품 요구에 남겨두며, 전체 제품에서 삭제한 것은 아니다.

| 기능 | 1차 핵심 기능 | 2차 확장 기능 |
| --- | --- | --- |
| 기존 자료 활용 | 제공 자료를 한 번 반영하고 기준정보를 참조 | 다른 매장 자료와 추가 기준정보 지원 |
| 판매 관리 | 기존 메뉴의 판매를 직접 입력·수정·삭제 | 반품·취소 등 추가 판매 유형, 다양한 일괄 처리 |
| 비용 관리 | 기존 비용항목의 기록을 직접 입력·수정·삭제 | 월 계획 편집과 계획 대비 실적 비교 |
| 메뉴 수익성 | 재료·포장·결제수수료를 고려한 메뉴별 결과와 비교. 임차료·인건비 등은 매장 전체 손익에서 확인 | 좋은 메뉴·개선 필요 메뉴 등 기준에 따른 분류, 상세 비교 |
| 실제 기간 손익 | 기록된 판매·비용으로 기간 실적과 손익 확인 | 기간 간 비교와 더 자세한 분석 |
| 예상 손익 | 1차에서 보류 | 실제 실적과 구분된 예상 결과 및 전망 전제 확인 |
| 재고 기록 | 입고·폐기·실제 센 수량 기록, 재료별 잔량 확인 | 재고 기록의 추가 수정·삭제 관리, 변동 이력 분석 |
| 부족한 재료 | 재료별 최소 수량에 따른 기본 확인. 실제 기준값은 후속 설정 사항 | 납기·안전재고 등을 고려한 사전 부족 예상 |
| 발주 참고 | 1차에서 보류 | 필요한 발주량과 공급사 정보 참고. 자동 발주는 별도 검토 |
| 조회 기간 | 일·월 조회 | 주·분기·반기·연간 조회 |
| 엑셀 업무 | 1차에서 보류 | 판매·비용 입력 양식 내려받기와 해당 양식 가져오기; 재고 양식은 추가 협의 |
| 저장·백업·복원 | 작성 내용 저장, 수동 백업과 복원 | 자동 백업, 여러 백업본 관리, 여러 기기 사용 |
| 메뉴·재료·레시피 관리 | 제공 기준정보를 참조 | 신규 등록·수정과 가격·레시피 변경 관리 |

1차는 매장 한 곳의 기본 운영을 확인하는 작은 버전을 목표로 한다. 로그인·직원 권한, 다른 판매 시스템 연동, 실제 주문 처리, 자동 발주, 회계·세무 신고, 날씨 분석은 1차 범위에 포함하지 않는다. 저장 위치, 배포 방식, 대상 기기의 구체적인 조건은 후속 설계에서 정한다.

## 5. 1차 기능 요구사항

다음은 사용자 관점의 기능 요구다. 입력 칸 구성, 화면 배치, 버튼 순서와 구체적인 처리 절차는 다음 설계 단계에서 정한다.

| 번호 | 요구사항 | 사용자가 얻는 결과 |
| --- | --- | --- |
| M01 | 제공된 메뉴·재료·레시피·가격·달력·초기재고와 운영 기록을 참조할 수 있다. | 샘플을 다시 입력하지 않고 핵심 흐름을 확인한다. |
| M02 | 판매를 직접 입력·수정·삭제할 수 있다. 날짜·메뉴·매장 또는 포장 구분과 판매 내용을 관리한다. | 판매 변경이 메뉴 결과, 기간 손익, 재료 잔량에 일관되게 반영된다. |
| M03 | 비용을 직접 입력·수정·삭제할 수 있다. | 비용 변경이 해당 기간 손익에 반영된다. |
| M04 | 선택한 기간의 메뉴별 판매 실적과 수익성을 확인할 수 있다. | 재료·포장·결제수수료를 고려해 메뉴가 운영비에 보탠 금액을 확인한다. 임차료·인건비 등 운영비는 메뉴별로 나누지 않고 매장 전체 손익에서 확인한다. D01의 사용자 선택 A를 반영했다. |
| M05 | 선택한 기간의 매출·비용·손익을 확인할 수 있다. | 실제 포함된 기간과 기록 완료 여부를 이해한다. 메뉴 수익성과 매장 전체 손익의 차이를 설명할 수 있어야 한다. |
| M06 | 재료의 입고·폐기·실제 센 재고를 기록할 수 있다. | 판매 외 재료 변동을 관리하고, 실제 센 수량을 해당 기준 시점의 재고 기준으로 삼는다. |
| M07 | 기준일의 재료 잔량과 재료별 최소 수량에 못 미치는 재료를 확인할 수 있다. | 재료명, 수량 단위, 잔량의 기준 시점을 이해하고 재료 보충 필요성을 확인한다. 최소 수량이 정해지지 않은 재료는 부족 여부를 확정하지 않는다. |
| M08 | 일·월 단위로 핵심 결과를 조회할 수 있다. | 같은 조회 기간으로 메뉴와 매장 결과를 확인한다. 재고는 기간 실적과 구분되는 기준일의 잔량으로 확인한다. |
| M09 | 입력한 내용을 저장하고 다시 이용할 수 있다. | 프로그램을 다시 열어도 이전 기록을 확인한다. |
| M10 | 한 기기에서 사용하는 자료를 수동으로 백업하고 복원할 수 있다. | 기록과 결과에 필요한 기준정보를 보존하고, 백업본으로 핵심 흐름을 다시 이용한다. 기존 자료와 복원 자료의 처리 절차는 후속 설계에서 정한다. |

과거 판매 당시 기준 유지, 비용 실적·계획 구분, 실측 재고를 기준으로 삼는 방향, 최소 수량에 따른 부족 판단을 채택했다. 새 판매와 수정 기록의 원가·수수료 처리, 비용과 재고의 상세 반영 방식, 재료별 최소 수량은 후속 설계 사항이다. 이 문서는 그 계산식이나 처리 절차를 정하지 않는다.

## 6. 핵심 사용 시나리오

1. 운영자가 기존 메뉴의 판매 기록을 추가한다. 예: 카페라떼의 매장 판매와 포장 판매를 구분해 기록한다.
2. 해당 날짜 또는 월의 메뉴별 결과를 확인해 카페라떼가 수익에 얼마나 도움이 되는지 본다.
3. 같은 기간의 비용을 확인하거나 수정하고, 매장 전체 손익을 확인한다.
4. 재료 잔량을 확인한다. 예: 우유와 포장컵은 각자의 단위로 확인한다.
5. 입고·폐기·실제 센 수량을 기록한 뒤, 합의한 재고 기준에 따른 잔량과 부족 여부를 확인한다.
6. 내용을 저장하고 백업한다. 나중에 다시 열거나 복원해 동일한 기록과 결과를 확인한다.

예시에 등장하는 메뉴와 재료는 자료에 있다. 예시 판매수량이나 부족 기준은 제품 정책으로 확정하지 않는다.

## 7. 4시간 구현 범위와 시간 예산

기획부터 배포까지 총 240분의 목표 예산이다. 업무 기준의 빠른 합의, 기존 개발 환경과 배포 수단의 사용 가능 여부에 따라 달라지며, 기능별 완료를 보장하는 견적은 아니다. 환경과 사용할 기기는 구현 전에 확인한다.

| 단계 | 시간 | 목표 |
| --- | ---: | --- |
| 기획 | 25분 | 1차 범위와 핵심 업무 기준 합의 |
| 화면 설계 | 20분 | 핵심 흐름을 이용하는 최소 구성 결정 |
| 개발 | 130분 | 자료 반영, 기록 관리, 연결된 결과, 저장·백업·복원 |
| 검사 | 35분 | 아래 완료 기준을 대표 사례로 확인 |
| 배포 | 15분 | 합의한 사용 환경에서 실행과 재접속 확인 |
| 여유 시간 | 15분 | 발견된 핵심 오류 수정 |
| 합계 | **240분** | 작은 첫 버전의 핵심 흐름 완성 |

시간을 지키기 위해 기준정보 편집, 엑셀 가져오기·양식 생성, 예상 손익, 발주량 전망, 추가 기간 조회는 2차로 정했다. 차트나 꾸미기보다 판매 변경과 손익·재고의 연결, 저장한 기록의 보존을 우선한다.

핵심 흐름이나 저장·복원이 검사에서 실패하면 완료로 처리하지 않는다. 시간이 부족할 경우 범위 조정을 제안하고 합의하며, 조용히 요구사항을 빼거나 예상값을 실제값처럼 제공하지 않는다.

## 8. 1차 완료 기준

구현 검사 때 사용할 결과 기준이며, 구체적인 검사 코드나 계산식은 여기서 정하지 않는다.

- 제공 자료를 반영했을 때 같은 기록이 두 번 들어가지 않는다.
- 판매 추가·수정·삭제가 메뉴 결과, 해당 기간 손익, 관련 재료 잔량에 함께 반영된다.
- 비용 추가·수정·삭제가 해당 기간 손익에 반영되고, 월 계획과 비용기록을 같은 지출로 중복 반영하지 않는다.
- 동일 메뉴의 매장·포장 판매 차이가 보존된다.
- 과거 기록은 합의 없이 현재 가격으로 변경되지 않는다.
- 입고·폐기·실제 센 수량이 합의한 재고 정책에 맞게 구분되어 반영된다.
- g·ml·개를 혼동하지 않고 재료별 기준일 잔량을 확인할 수 있다.
- 부족 여부는 합의한 기준에 따라 확인되며, 기준이 없는 상태에서 임의 판정을 하지 않는다.
- 미마감·누락·0을 구분하고, 조회 결과의 실제 포함 기간을 이해할 수 있다.
- 필요한 정보가 없는 경우 결과를 0이나 확정값으로 오해하게 하지 않는다.
- 일·월 조회가 같은 기록과 기간 기준을 사용한다.
- 저장 후 다시 열어도 기록이 보존되고, 백업 복원 후 기록과 핵심 결과를 다시 확인할 수 있다.

## 9. 채택한 방향과 후속 설계 사항

### 9.1 채택한 방향

2026-10-12 사용자 답변 “A”와 이어진 “모두 추천으로 해줘”에 따라 아래 방향을 반영했다. 기존 추천이 없던 재고 기준은 일괄 추천 요청에 따라 기획 담당자가 선택했다. 기능 범위에 대한 추가 선택 질문은 마무리한다. 세부 수치나 이번 문서에서 다루지 않기로 한 사항까지 확정한 것은 아니다.

| 번호 | 항목 | 채택한 방향과 쉬운 예시 | 추천 이유 |
| --- | --- | --- | --- |
| D01 | 메뉴 수익성 | 재료·포장·결제수수료를 고려해 메뉴가 운영비에 보탠 금액을 확인한다. 임차료·인건비는 매장 전체 손익에서 본다. | 메뉴별 운영비 배분이 필요 없어 핵심 흐름에 집중할 수 있다. |
| D02 | 과거 판매 평가 | 판매 당시 원가·수수료 기록을 유지한다. 오늘 원두 가격이 올라도 지난달 판매 결과가 자동으로 달라지지 않는다. | 실제 과거 실적의 의미를 유지한다. 현재 기준의 별도 참고 평가는 1차에서 제외한다. |
| D03 | 실측 재고 | 실제 센 수량을 해당 기준 시점의 재고 기준으로 삼는다. 우유가 기록에는 2,000ml, 실측은 1,800ml이면 실제 확인된 재고를 운영 기준으로 삼는다. | 실제로 사용할 수 있는 재료량을 중심으로 운영할 수 있다. 기록상 차이와 실측은 구분한다. |
| D04 | 부족한 재료 | 1차는 재료별 최소 수량에 못 미치는지 확인한다. 미래 판매·납기를 고려한 부족 전망은 2차다. | 전망 기능 없이 기본적인 보충 필요성을 확인한다. 최소 수량의 실제 값은 후속 설정 사항이다. |
| D05 | 비용과 계획 | 비용기록으로 실제 기간 손익을 확인하고, 월비용계획은 계획 참고로 구분한다. 9월 18일까지의 실적과 9월 전체 계획을 같은 실적에 더하지 않는다. | 비용 중복과 실적·계획 혼동을 피한다. |
| D06 | 전망과 발주 참고 | 예상 손익과 권장 발주량은 2차로 진행한다. 전망 대상 기간은 2차 기획에서 정한다. | 실제 기록의 연결을 먼저 완성한다. 아직 이번 달 또는 다음 달로 기간을 확정하지 않는다. |
| D07 | 사용자와 단계 구분 | 매장 한 곳·운영자 한 명으로 시작한다. 4장의 1차·2차 구분을 채택한다. | 권한·동시 사용·다중 매장 관리 범위를 줄여 4시간 목표에 맞춘다. |
| D08 | 저장과 백업 | 한 기기에서 저장해 사용하며, 수동 백업·복원을 제공한다. 여러 기기의 자료 공유와 자동 백업은 2차다. | 기록 보존에 필요한 기능을 우선 완성한다. |
| D09 | 기간과 마감 | 1차는 일·월 조회와 마감 여부 구분을 제공한다. 다른 기간 조회는 2차다. | 미마감 날짜를 매출 0으로 오해하지 않으면서 조회 범위를 줄인다. |
| D10 | 분류와 예외 판매 | 1차는 메뉴별 수익성 수치와 비교를 제공한다. 좋음·개선 필요 같은 자동 분류와 반품·취소 등 추가 판매 유형은 2차다. | 새로운 분류 기준과 예외 처리 범위를 줄인다. |

### 9.2 이 PRD 밖에서 다루는 사항

다음 항목은 제품 범위를 설명하는 PRD에 계산식·기술·상세 동작을 넣지 않기 위해 분리한 사항이다. 2026-10-12 추천 기준으로 문서를 완료하라는 후속 지시에 따라 1차 업무 동작·계산은 FRD, 구현 방식은 TRD에 정리한다. 실제 최소 수량과 2차의 구체적인 기준은 자료에서 확인된 값으로 간주하지 않는다.

| 사항 | 남겨두는 내용 | 정할 시점 |
| --- | --- | --- |
| 원가·수수료 | 새 판매와 수정 기록에 적용할 기준 및 계산식 | 1차 구현 전 업무 규칙 설계 |
| 비용 반영 | 비용 변경과 월 계획의 관계, 상세 배분 방식 | 1차 구현 전 업무 규칙 설계 |
| 재고 반영 | 실측 시점과 판매 수정의 관계, 기존 조정 기록 반영 방식 | 1차 구현 전 업무 규칙 설계 |
| 부족 기준값 | 재료별 최소 수량의 실제 값. 자료의 안전재고 일수를 최소 수량으로 바로 간주하지 않는다. | 1차 구현 전 설정 범위 설계 및 실제 사용 전 운영 값 설정 |
| 조회·마감 | 기록 완료 판정의 상세 기준; 주의 시작일과 연간 기준 | 마감 기준은 1차 설계, 추가 기간 기준은 2차 설계 |
| 저장·복원 | 저장 위치·파일 형식·기존 자료와 복원 자료의 관계·복원 절차 | 1차 구현 전 상세 설계 |
| 전망 | 예상 손익·발주량의 대상 기간, 전망 방법과 전제 | 2차 기획 |
| 화면·기술·배포 | 화면 디자인, 구현 기술, 상세 동작, 코드, 대상 기기 조건과 배포 수단 | 후속 화면 설계·개발 계획 |

후속 설계에서는 이번에 채택한 방향을 우선 적용한다. 기존 방향을 바꾸거나 1차 범위를 늘려야 하는 경우에는 변경 내용을 별도로 알린다.

## 10. 이번 문서의 경계

이 PRD는 목적, 자료의 사실, 기능 요구, 단계별 범위, 완료 기준과 미정 항목을 다룬다. 계산식, 수익성 분류의 수치 기준, 전망 방법, 비용 배분식, 화면 디자인, 구현 기술, 상세 처리 절차, 코드와 배포 수단은 이후 작업에서 정한다. 후속 설계도 이 문서의 미정 항목을 임의로 합의 완료로 취급하지 않는다.

## 11. 연결 문서와 완료 상태

PRD 작성은 완료했다. 제품 목적, 자료 사실, 1차·2차 기능, 4시간 목표를 유지한다. 사용자 지시에 따른 추천 동작·계산 기준은 [02_FRD.md](02_FRD.md), 구현 방법은 [03_TRD.md](03_TRD.md)에 정리했다. 이 문서에 계산식·화면 디자인·기술·코드를 추가하지 않는다. 실제 최소 수량은 운영 입력 값이며, 2차의 전망 기준 등은 확장 시 정한다. 문서 완료는 프로그램 구현·검사·배포 완료와 구분한다.
