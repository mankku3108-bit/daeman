# 카페 판매·손익·재고 관리 기능 요구사항 문서

- 작성일: 2026-10-12
- 상태: 1차 기능·계산·동작 기준 정리 완료. 2026-10-12 사용자의 추천 기준으로 완료하라는 지시를 반영했다. 실제 최소 수량과 2차 정책은 별도 운영·확장 사항이다.
- 범위 근거: 확정된 PRD의 1차·2차 구분을 유지한다. 시안에만 있는 추가 기능은 미승인 상태이며 1차 요구사항에 추가하지 않는다. 시안의 문구·버튼을 어떻게 보완할지는 제안으로 구분한다.
- FRD: 사용자가 어떤 일을 하면 프로그램이 무엇을 처리하고 어떤 결과를 내는지 설명하는 기능 요구사항 문서.

## 1. 프로그램의 목적과 문서 읽는 방법

매장 한 곳의 운영자 한 명이 한 기기에서 판매·비용을 입력·수정·삭제하고, 메뉴 수익성과 일·월 손익, 재료 잔량을 확인한다. 재료 입고·폐기·실제 센 수량을 기록하고, 자료를 저장·백업·복원한다.

핵심 흐름은 **판매 입력 → 메뉴 수익성 → 기간 손익 → 재료 잔량·부족 확인**이다. 판매 변경은 관련 결과에 함께 반영되어야 한다. 임차료·인건비 등 운영비는 메뉴에 나누지 않고 매장 전체 손익에서 확인한다.

### 1.1 상태 표시

- **확정 요구:** PRD 또는 이번 대화로 정한 기능·업무 방향. 시안에 없어도 구현 범위에 포함한다.
- **확인 사실:** 실제 자료와 시안에서 확인한 내용. 시안의 예시 값은 제품 정책으로 확정된 값이 아니다.
- **채택한 동작·계산:** 기존 초안의 추천을 9장의 기준으로 구체화해 채택했다. 앞장의 “제안·추천” 표현은 채택 근거를 설명하며, 세부 기준은 9장의 완료 기준을 따른다.
- **미정:** 선택이나 실제 운영 값이 필요한 부분. 임의의 숫자·정책으로 채우지 않는다.
- **2차:** 전체 제품 요구에는 있으나 1차에서는 구현하지 않는 기능.

5~7장의 1차 동작·계산·오류 대응은 9장의 채택 기준에 따라 적용한다. 8장의 2차 기능과 미승인 추가 기능은 1차로 승격하지 않는다. 시안 예시와 실제 운영 값은 구분한다. 문서 완료는 프로그램 개발·검사·배포 완료를 뜻하지 않는다.

### 1.2 쉬운 용어

| 용어 | 뜻 |
| --- | --- |
| 판매 기록 | 주문 한 건이 아니라 같은 날짜·메뉴·매장/포장별로 모은 판매 내용 |
| 순매출 | 판매금액에서 할인 총액을 반영한 금액. 결제수수료를 뺀 통장 입금액과 다르다. |
| 공헌이익 | 재료비·포장비·결제수수료를 고려한 뒤 메뉴가 운영비에 보탠 금액 |
| 공헌이익률 | 순매출 중 공헌이익이 차지하는 비율 |
| 운영 손익 | 메뉴들의 공헌이익과 같은 기간 운영비를 함께 본 매장 전체 결과 |
| 당시 원가 사본 | 판매 당시 적용한 개당 원가를 판매 기록에 남긴 값. 오늘 가격이 올라도 자동 변경하지 않는다. |
| 장부 잔량 | 판매·입고·폐기·실사 기록을 반영해 구한 재료 잔량 |
| 실사·실측 | 실제로 재료 수량을 세거나 측정하는 일 |
| 실사조정량 | 실제 센 수량과 실사 직전 장부 잔량의 차이 |
| 마감 | 해당 날짜의 기록 작성을 끝냈다는 표시. 현금 정산이나 장부 잠금을 뜻하는지는 별도 결정이 필요하다. |
| 백업·복원 | 기록과 기준정보를 파일로 보관하고, 그 파일로 다시 사용 가능한 상태를 만드는 일 |

## 2. 확인한 자료와 시안

### 2.1 자료와 출처

기준 문서는 [01_PRD.md](01_PRD.md)다. 시안은 아래 세 화면의 PNG와 HTML을 모두 검토했다. [디자인 설명](../design/artisan_ember_smoke/DESIGN.md)은 색·글꼴·스타일 참고 자료이며 숯불구이 매장을 대상으로 한 설명도 포함한다. 카페의 기능이나 업무 정책의 근거로 사용하지 않는다. 기존 `02_FRD.md` 초안을 검토해 보완했으며, 기존 파일 안의 승인 문구만으로 사용자 승인을 추정하지 않았다.

| 시안 | 확인한 화면 | 근거 파일 |
| --- | --- | --- |
| S01 | 종합 대시보드, 빠른 업무 버튼, 메뉴 공헌이익, 부족 재료 | [이미지](../design/_1/screen.png), [HTML](../design/_1/code.html) |
| S02 | 재고 목록과 실사 등록창 | [이미지](../design/_2/screen.png), [HTML](../design/_2/code.html) |
| S03 | 판매 목록과 판매 등록·수정창 | [이미지](../design/_3/screen.png), [HTML](../design/_3/code.html) |

자료 의미는 [데이터설명.md](../data/데이터설명.md)와 PRD의 검토 결과를 따른다. 엑셀과 JSON은 같은 가상 매장 자료다. 메뉴 8개, 재료 11개, 레시피 22행, 판매 6,112행, 초기재고 11행, 재고 변동 1,515행, 비용 3,560행, 월비용계획 120행이 있다. 금액은 원·부가세 제외이며 재료 단위는 g·ml·개다.

판매·비용 실적은 2025-07-01~2026-09-18 마감까지다. 2026-09-19~09-30에는 미마감 영업달력만 있으므로 그 기간을 매출 0으로 넣지 않는다. 현재 날짜가 2026-10-12여도 자료의 마지막 기록일을 오늘로 바꾸지 않는다.

HTML의 실제 작동은 제품 완성을 의미하지 않는다. S01·S02는 대부분 정적 표시다. S03의 계산은 라떼 원가·원두·우유·3% 수수료를 고정한 시연이며 메뉴·채널·날짜 변경과 연동되지 않는다. 저장 버튼도 완료 문구를 보여주는 시연일 뿐 기록 보존을 구현한 근거가 아니다.

## 5. 기능별 작동 요구사항

각 기능의 화면 결과와 저장 결과를 구분한다. 보통의 등록·조회는 별도 파일을 내려받지 않는다. 파일 출력은 F15 백업에서만 발생한다. 파일은 JSON 백업이며 프로그램 저장은 TRD의 브라우저 저장소를 사용한다.

### F01. 기존 자료 최초 반영과 기준정보 참조 — M01

**확정 요구:** 제공 자료를 한 번 반영하고 메뉴·재료·레시피·가격·달력·초기재고를 참조한다.

1. 프로그램의 최초 사용 시 제공 자료 한 형식을 반영한다. 추천은 제공 JSON 한 번 반영이며, 운영자용 임의 파일 가져오기 기능을 1차에 추가하는 뜻이 아니다.
2. 프로그램은 기록 수·고유ID·연결된 메뉴/재료·단위·날짜를 확인한다. 어느 자료를 반영했는지 보존하고 재접속 때 초기 자료를 다시 추가하지 않는다.
3. 완료하면 기존 기록이 판매·비용·재고 목록과 계산에 나타난다. 메뉴 선택은 기존 8개, 재료 선택은 기존 11개를 사용한다.
4. 저장 결과는 제공된 기록과 필요한 기준정보다. 원본 엑셀·JSON 파일은 수정하지 않는다. 다운로드는 없다.

**오류·예외:** 파일 손상·미지원 구조·중복ID·연결 대상 누락·단위 불일치가 있으면 문제 위치와 이유를 알리고 전체 반영을 중단하는 것을 추천한다. 일부만 반영해 정상 결과처럼 보이지 않게 한다. 기존 자료가 있으면 최초 반영을 반복하지 않는다. 반영 실패 후 재시도해도 중복되지 않아야 한다.

### F02. 화면 이동과 일·월 조회 — M08

**확정 요구:** 일·월 조회, 같은 기간의 메뉴·매장 결과, 기준일 재고를 제공한다.

1. 운영자가 일간/월간을 선택하고 날짜/월을 지정한다. 추천 초기 조회일은 오늘이 아니라 자료의 마지막 완료일이다.
2. 일간은 해당 날짜, 월간은 해당 월의 실제 기록 구간을 사용한다. 월 전체 범위와 실제 완료 구간을 함께 표시한다. 미마감 날짜에 입력된 자료는 잠정 기록으로 구분하고 완료 실적과 섞지 않는 방향을 추천한다(Q07).
3. 판매 목록은 메뉴·채널·ID/이름 검색을 함께 적용한다. 판매 합계의 기본 대상은 해당 날짜/월과 현재 필터에 맞는 전체 기록이며 페이지 하나의 행만 더한 값과 구분한다.
4. 재고는 조회일의 기준 잔량을 본다. 월간에서는 그 월의 마지막 완료일 잔량을 추천한다. 재고를 일별 합계처럼 더하지 않는다.
5. 조회·검색·페이지 이동은 원본 기록을 변경하거나 파일을 만들지 않는다. 첫/마지막 페이지에서 이전/다음을 막고 조건 변경 시 첫 페이지로 돌아간다.

**오류·예외:** 잘못된 날짜·월은 조회하지 않고 수정할 항목을 알린다. 기록 범위 이전/이후는 “자료 없음” 또는 “미마감”을 구분한다. 완료된 영업일에 판매가 없는 경우만 0 실적으로 설명할 수 있다. 초기재고 이전의 잔량은 추정하지 않는다. 빈 검색결과와 프로그램 읽기 실패를 같은 “0건”으로 표시하지 않는다.

### F03. 판매 목록과 신규 판매 입력 — M02

**확정 요구:** 기존 메뉴의 판매를 날짜·메뉴·매장/포장별로 직접 등록한다.

| 입력 | 동작 제안과 검사 |
| --- | --- |
| 판매 일자 | 필수 유효 날짜. 해당 날짜의 원가 기준 선택은 Q03. 휴무·완료일 입력은 Q07 규칙 적용. |
| 메뉴 | 기존 메뉴 선택 필수. 표시 이름이 아니라 메뉴ID로 연결한다. |
| 채널 | 매장/포장 중 하나 필수. 메뉴의 해당 채널 레시피를 적용한다. |
| 수량 | 1 이상 정수 추천. +1/+5/+10은 입력 편의 기능이다. 최대 500은 확정하지 않는다. |
| 판매단가 | 메뉴 기준가를 초기 제안값으로 보여주되 운영자가 실제 단가를 입력한다. 부가세 제외 원 단위. |
| 할인 총액 | 해당 집계행 전체 할인액. 개당 할인액과 구분한다. 0 이상, 수량×단가 이하 추천. |
| 수수료 | 과거 기록은 기존 금액 보존. 새 기록은 실제 수수료 금액 직접 입력(Q02). 시안에 보완할 요소. |
| 원가·재료 사용 | 직접 고정 숫자를 넣지 않고 날짜·메뉴·채널·레시피에 따라 참조한다는 제안. 값과 적용 근거를 미리 보여준다. |

입력하는 동안 F04 미리보기만 바뀐다. “저장”을 누르면 필수 입력·중복·연결 자료를 검사하고, 판매 기록과 수익성·손익·재고 결과를 함께 반영한다. 완료 후 목록에 해당 기록과 ID를 표시한다. 별도 다운로드 파일은 만들지 않는다.

**오류·예외:** 빈칸, 존재하지 않는 메뉴, 음수·소수 수량, 잘못된 금액, 할인 과다, 없는 레시피/단가, 중복 조합이면 해당 항목과 해결 방법을 표시한다. 잘못된 할인 때문에 순매출을 조용히 0으로 바꾸지 않는다. 단가 0 또는 전액 할인 판매도 허용한다. 수수료는 실제 금액으로 남긴다. 숫자 규칙은 Q04를 따른다. 미래 날짜를 완료 실적으로 입력하는 것은 막는 방향을 추천한다. 재고 음수·부족은 경고 후 실제 기록을 저장하고 수량을 0으로 덮지 않는다(Q05).

### F04. 판매 계산 미리보기와 취소 — M02·M04·M07

**확정 요구:** 판매 내용이 관련 결과와 일관되게 연결된다. **시안 확인:** 저장 전 순매출·수수료·원가·공헌이익·사용 재료 표시가 있다.

1. 날짜·메뉴·채널·수량·판매단가·할인·수수료 기준 중 하나를 바꾸면 C01~C03·C07을 다시 계산한다.
2. 메뉴 한 개의 식재료·포장 원가, 전체 원가, 사용 재료 수량과 단위를 표시한다. 매장 판매에 포장 전용 재료를 넣지 않는다.
3. 미리보기는 “저장 전 계산”으로 구분한다. 미래 매장 손익 전망이나 실제 통장 입금액으로 설명하지 않는다. 필수 기준이 없으면 해당 계산을 “계산 불가: ○○ 없음”으로 표시한다.
4. 닫기·취소는 저장하지 않는다. 값이 바뀌었다면 입력을 버릴지 확인하는 것을 추천한다. 취소 후 기존 판매와 잔량은 그대로다.

**오류·예외:** 수량 빈칸·수수료 미입력·가격이력 누락이면 0을 대신 넣어 이익을 부풀리지 않는다. 음수 공헌이익은 음수 그대로 표시하며 저장 허용은 입력값의 유효성으로 판단한다. 순매출 0이면 공헌이익률을 계산할 수 없다고 표시한다. 창을 열거나 계산할 때 재료를 차감하지 않는다.

### F05. 판매 수정 — M02

**확정 요구:** 기존 판매를 수정하고 관련 결과를 함께 반영한다. 당시 가격이 오늘 가격으로 자동 변경되지는 않는다.

1. 행의 수정 버튼을 누르면 해당 ID의 저장된 값과 당시 원가·수수료를 불러온다. 신규 기본값으로 덮지 않는다.
2. 입력 변경을 F04에서 미리 계산한다. 날짜·메뉴·채널·수량별 수정 기준은 Q03에 따른다.
3. 저장하면 기존 기록을 한 번 교체하고 같은 ID를 유지한다. 변경 전 판매 효과를 제거하고 변경 후 효과를 반영한다. 날짜를 바꾸면 이전·새 날짜의 기간 결과를 모두 갱신한다.
4. 관련 재료와 이후 재고를 다시 확인한다. 실측 이전 판매를 수정한 경우 Q05 정책에 따라 실측 기준과 이후 잔량을 처리한다.

**오류·예외:** 대상 기록이 없거나 다른 저장으로 이미 바뀌었으면 새로 불러오도록 안내하고 덮어쓰지 않는다. 수정 후 동일 날짜·메뉴·채널의 다른 기록과 충돌하면 Q09를 따른다. 실패 시 원래 기록과 결과를 유지하고 입력값을 보존한다. 수량 감소를 신규 판매의 음수 입력으로 처리하지 않는다.

### F06. 판매 삭제 — M02

**확정 요구:** 판매 기록을 삭제하고 수익성·손익·재고 결과에서도 그 기록의 효과를 제거한다.

1. 행 또는 수정창의 기록 삭제를 누르면 날짜·메뉴·채널·수량을 보여주고 삭제 여부를 확인한다. 신규 등록창에는 삭제할 기록이 없으므로 삭제 동작을 막는다.
2. 확인하면 해당 ID 한 건을 제거하고 관련 기간과 재료 잔량을 갱신한다. 실사 이전의 기록이면 Q05를 따른다.
3. 취소하면 아무것도 바뀌지 않는다. 삭제 후 목록·검색·페이지 수와 요약이 일치해야 한다.

**오류·예외:** 이미 삭제된 ID를 또 삭제해도 재고를 두 번 증가시키지 않는다. 삭제 후 비용이나 실측 기록을 자동 삭제하지 않는다. 저장 실패 시 삭제 성공으로 표시하지 않고 기존 상태를 유지한다. 삭제 되돌리기·휴지통·감사 이력은 1차 새 기능으로 추가하지 않는다.

### F07. 비용 목록·입력·수정·삭제 — M03

**확정 요구:** 기존 8개 비용항목으로 날짜별 비용기록을 관리한다. 월 계획 편집은 2차다. 상세 화면은 시안에 없다.

1. 비용 관리 또는 비용 전표 입력에서 귀속일·기존 비용항목·금액을 입력한다. 귀속일은 그 비용이 해당되는 날짜임을 설명한다. 필수 입력칸 보완은 기존 M03 구현을 위한 제안이다.
2. 저장 시 날짜·항목·금액을 검사하고 고유 비용ID로 보존한다. 월 계획을 자동으로 수정·복제하지 않는 방향을 추천한다(Q10).
3. 목록에서 기간·항목·금액을 확인하고 기존 ID를 수정·삭제한다. 삭제 확인·실패 대응은 판매와 같은 원칙을 적용한다.
4. 비용 변경은 해당 기간의 운영비 합계와 손익만 바꾼다. 메뉴 공헌이익이나 재료 수량을 직접 바꾸지 않는다. 원본 파일과 다운로드 파일은 생성·수정하지 않는다.

**오류·예외:** 날짜·항목 누락, 비숫자·음수 금액은 저장하지 않는 것을 추천한다. 0원 비용을 허용하며 빈칸은 허용하지 않는다(Q04). 같은 날짜·항목의 비용이 여러 건이라고 자동 합치거나 중복 삭제하지 않는다. 비용ID 중복은 막는다. 월 계획과 기록 차이는 실적 누락을 뜻한다고 단정하지 않는다. 비용 변경으로 적자가 되면 음수 손익을 그대로 표시한다.

### F08. 메뉴별 수익성 확인 — M04

**확정 요구:** 메뉴별 실적과 재료·포장·수수료 반영 후 공헌이익을 비교한다. 운영비 배분과 자동 분류는 1차에 없다.

1. 메뉴 수익성 또는 대시보드에서 일·월을 조회하면 기존 메뉴와 채널별로 판매수량·순매출·식재료비·포장비·수수료·공헌이익·공헌이익률을 집계한다(C01~C04).
2. 동일 메뉴의 매장/포장을 구분한다. 메뉴 전체 합계를 제공할 때는 두 채널을 합친 값임을 알린다. 같은 기록을 채널별과 메뉴 합계에서 중복 더하지 않는다.
3. 별도 수익성 화면은 전체 8개 메뉴를 확인할 수 있어야 한다. 대시보드 일부 행만 보고 전체 결과라고 오해하지 않게 표시한다.
4. 전체 메뉴를 기존 메뉴ID 순으로 제공하며 상위 5개 자동 순위 기능은 넣지 않는다. 좋은 메뉴/개선 필요 같은 자동 판정은 하지 않는다. 조회는 기록을 바꾸거나 파일을 만들지 않는다.

**오류·예외:** 완료 기간에서 판매 없는 메뉴는 판매 0을 표시할 수 있지만 이익률은 계산 불가로 구분한다. 원가·수수료 누락이 있는 메뉴는 불완전 결과와 누락 건수를 표시하고 정상 합계처럼 확정하지 않는다. 결과가 음수이면 그대로 표시한다. 메뉴명의 변경·누락 때문에 다른 메뉴로 합치지 않는다.

### F09. 실제 기간 손익과 대시보드 — M05

**확정 요구:** 순매출·관련 비용·운영 손익과 포함 기간을 확인한다. 예상 손익은 2차다.

1. 같은 조회 범위의 판매와 날짜별 비용을 모아 C05로 계산한다. 월비용계획은 실적 비용에 더하지 않는다.
2. 화면에 총 순매출, 식재료·포장·수수료 비용, 운영비, 손익을 표시한다. 비율을 표시할 경우 분모를 순매출로 설명한다(C06).
3. 일부 기간만 마감됐다면 “9월 1~18일 완료 실적”처럼 표시한다. 매출 행 수를 주문 수나 고객 수로 부르지 않는다. 음료와 디저트의 개수를 모두 “잔”으로 표현하지 않는다.
4. 메뉴 공헌이익 합계와 운영비 차이가 매장 손익으로 연결되어야 한다. 폐기·실사 차이는 재고 수량에 반영하고 손익 금액에는 별도 반영하지 않는다. “판매·운영비 기준 손익, 재고 손실 금액 미반영”을 함께 알린다(Q11).
5. 화면 조회만으로 파일을 출력하지 않는다. 현금 잔액·부가세·세금 신고·통장 입금액을 계산하지 않는다.

**오류·예외:** 매출 0이면 비용과 음수 손익은 표시하되 원가율·손익률은 계산 불가다. 비용 누락이나 미마감 자료가 있으면 0이라고 단정하지 않는다. 일부 데이터 계산 실패를 정상인 다른 합계로 숨기지 않는다. 휴무일에 월 비용이 배분되어 있어도 자료 오류로 자동 삭제하지 않는다.

### F10. 재료 입고·폐기·실측 등록 — M06

**확정 요구:** 세 유형을 기록하고 실제 센 수량을 해당 시점의 재고 기준으로 삼는다. 재고기록의 일반 수정·삭제는 2차다.

| 유형 | 입력 제안 | 처리·화면 결과 | 보존할 값 |
| --- | --- | --- | --- |
| 입고 | 기록일·기존 재료·입고한 양·사유. 필요한 경우 공급사·단위원가 | 양의 증가량으로 반영, 저장 전후 잔량 표시 | 날짜·재료·유형·양의 수량·단위·사유, 입력된 공급사·원가 |
| 폐기 | 기록일·기존 재료·버린 양·사유 | 사용자는 양을 양수로 입력하고 프로그램은 음의 증감량으로 보존하는 방식 추천 | 날짜·재료·유형·음의 증감수량·단위·사유 |
| 실측 | 기록일·기존 재료·실제 센 수량·사유 | 실사 직전 장부 잔량과 차이를 보여주고 저장 후 실측값을 해당 시점 기준으로 사용 | 날짜·재료·유형·실측수량·차이 수량·단위·사유 |

1. 날짜·재료를 선택하면 **그 기록 기준 시점의** 잔량과 단위를 보여준다. 날짜별 자료이므로 실사는 해당 날짜 영업 종료 시점으로 간주하는 것을 추천한다(Q05). 시안의 22:00을 실제 기록 시각으로 저장하지 않는다.
2. 유형 변경 시 수량 설명이 입고량/폐기량/실제 센 수량으로 바뀐다. 단위는 선택 재료에서 정하며 다른 단위로 임의 변경하지 않는다.
3. C07~C09에 따라 예상 잔량 또는 실사 차이를 표시하고, 저장하면 변동ID 한 건과 잔량·부족 결과를 반영한다. 취소는 아무것도 반영하지 않는다.
4. 공급사·입고 원가는 원자료에 있으나 시안에는 입력칸이 없다. 1차 신규 입고에서는 공급사·단위원가를 필수 입력으로 추가하지 않는다. 제공 자료에 있는 값은 보존한다(Q11). 입고 가격을 입력했다고 기준 가격이력을 자동 편집하지 않는다.

**오류·예외:** 미선택 재료·잘못된 날짜·단위 불일치·입고/폐기 0 이하·실측 음수는 막는 방향을 추천한다. 실측 0은 실제 소진으로 인정한다. g·ml의 소수 수량과 ‘개’의 정수 기준은 Q04. “4,000”은 쉼표를 제거해 4000으로 해석하되 숫자 이외 문자는 오류로 알린다. 4,000ml 실측을 +4,000ml 입고로 처리하지 않는다. 같은 날짜·재료 실사는 한 번만 허용한다. 초기재고 이전·미래 기록은 저장하지 않는다. 음수 잔량은 경고 후 보존하고 소급 수정은 Q05를 따른다.

### F11. 기준일 재료 잔량 목록 — M07

**확정 요구:** 재료별 잔량·단위·기준일을 확인한다.

1. 기존 재료 11개에 대해 초기재고·입고·판매사용·폐기·실사조정·기준일 잔량을 구한다(C07~C09).
2. 각 누적 항목이 최초 기준일부터 조회 기준일까지인지, 조회 월 안에서만인지 표시한다. 추천은 시안처럼 최초 기준일부터 누적하고 “현재 잔량” 대신 “선택 기준일 잔량”으로 명시한다.
3. 재료명/ID 검색과 페이지 이동은 현재 조건의 목록을 바꾼다. 목록이 5개 보인다고 관리 재료가 5개로 줄지 않는다.
4. 비용·판매 화면에서 같은 기준일을 확인하면 재고 결과가 일치해야 한다. 목록 조회는 기록을 바꾸거나 다운로드하지 않는다.

**오류·예외:** 초기재고·레시피 연결 누락은 해당 재료의 잔량을 계산 불가로 표시한다. 단위가 다른 재료량을 하나의 총수량으로 합치지 않는다. 잔량이 음수이면 Q05 규칙에 따른 경고를 표시하며 0으로 덮지 않는다. 실측 있는 기록의 실측값과 차이를 둘 다 증가·감소로 적용하지 않는다.

### F12. 최소 수량과 부족 재료 확인 — M07

**확정 요구:** 재료별 최소 수량보다 적은지 확인하고 기준이 없으면 판정을 보류한다. 실제 최소 수량 값은 아직 없다.

1. 기준일 잔량과 설정된 같은 단위의 최소 수량을 비교한다(C10). 화면에 잔량·기준·부족량을 표시한다.
2. 기준 미설정은 “기준 미설정·판정 보류”, 최소 수량보다 작은 경우 “부족”, 같거나 큰 경우 “기준 충족”을 추천한다. 발주량·긴급성·소진 전망과 구분한다.
3. 부족 재료만 보기에는 판정 가능한 부족 재료만 들어간다. 판정 보류 개수를 따로 알려 누락처럼 보이지 않게 한다.
4. 기존 재료별 최소 수량을 직접 입력할 최소 보완 수단을 제공한다(Q06). 기준을 수정하면 부족 판정만 바뀌고 실재고가 바뀌지 않는다. 일반 재료 편집이나 자동 기준 산정 기능을 추가하지 않는다.

**오류·예외:** 단위 불일치·음수·비숫자 기준값이면 저장하지 않는다. 미설정과 기준 0은 구분한다. 잔량 계산 불가이면 기준이 있어도 판정 불가다. “부족 0건”이 “모든 재료 안전”을 뜻하지 않도록 판정보류를 함께 표시한다.

### F13. 기록 완료·마감 상태 — M08 지원

**확정 요구:** 영업/휴무/완료/미완료를 구분하고 미래·미마감 날짜를 판매 0으로 보지 않는다. **시안 확인:** 마감 등록 버튼이 있다.

1. 마감 등록에서 날짜를 확인하고 그 날짜 기록이 끝났다고 표시하는 방향을 추천한다(Q07). 판매 입력 한 번으로 자동 마감하지 않는다.
2. 기록 없는 영업일을 마감할 때 실제 판매 0인지 확인한다. 원자료 달력의 완료 표시는 최초 반영 때 보존한다.
3. 완료 표시 후 조회의 완료 실적 범위가 바뀐다. 매출·비용을 자동 생성하거나 잔량을 실사한 것으로 표시하지 않는다.
4. 마감 후 판매·비용 수정은 허용하며 수정 날짜는 미완료로 바꿔 다시 마감하게 한다(Q07). 마감 잠금·재개방 권한은 아직 새 기능으로 채택하지 않는다.

**오류·예외:** 미래 날짜 마감은 막는 방향을 추천한다. 판매·원가 등 필수 기록 오류가 있는 날짜는 이유를 알려 마감하지 않는다. 마감 버튼을 두 번 눌러도 같은 날짜가 중복 생성되지 않는다. 달력 밖의 유효한 운영 날짜는 영업·미완료로 추가한다. 휴무일 판매는 영업 여부를 확인해 영업일로 바꾼 뒤 저장한다(Q07).

### F14. 저장과 재접속 — M09

**확정 요구:** 입력 기록을 저장하고 프로그램을 다시 열어 이용할 수 있어야 한다. 저장 기술·위치는 TRD의 브라우저 저장소 기준을 따른다.

1. 각 등록·수정·삭제의 확인 후 기록을 보존하고, 읽어 확인할 수 있는 상태가 된 뒤 “저장 완료”를 표시하는 방향을 추천한다.
2. 판매만 저장되고 재고가 예전 상태로 남지 않게 한다. 계산된 결과는 저장한 원기록과 같은 기준에서 다시 얻을 수 있어야 한다.
3. 재접속 시 기존 저장자료를 먼저 읽고 최초 샘플을 다시 덧붙이지 않는다. 저장은 백업 파일 다운로드와 다르다.
4. 저장 중에는 같은 동작을 중복 실행하지 못하게 한다. 실패하면 이전 확정 상태를 유지하고 입력을 남겨 재시도할 수 있게 한다.

**오류·예외:** 저장 공간 부족·접근 거부·중간 종료·읽기 손상은 실패 내용을 표시한다. 손상된 자료를 빈 데이터로 바꾸거나 샘플로 자동 덮지 않는다. 저장 완료 전 창을 닫으면 완료를 보장할 수 없음을 알린다. 실패 후 재시도는 같은 판매나 재고 변동을 두 번 만들지 않아야 한다. 재접속·이중 실행의 충돌 처리 수준은 한 기기 범위에서 후속 기술 설계한다.

### F15. 수동 백업과 복원 — M10

**확정 요구:** 한 기기의 기록과 기준정보를 백업하고 복원할 수 있어야 한다. 클라우드·자동 백업은 1차 제외다.

**백업 제안:** 데이터 백업/다운로드에서 마지막으로 저장 완료된 자료를 읽고 4장의 백업 대상을 파일 하나로 만든다. 작성 시각·자료 기준일·기록 수·백업 구조 버전을 포함해 식별할 수 있게 한다. 저장 전 입력은 포함하지 않았음을 알린다. 파일은 JSON으로 정하며 형식·파일명은 TRD를 따른다. 파일 생성 실패와 내려받기 취소를 백업 완료로 표시하지 않는다.

**복원 제안:** 파일 선택 → 읽기·검사 → 포함 기간·기록 수·기준정보·현재 자료에 미치는 영향 표시 → 사용자 확인 → 전체 반영 → 결과 재계산 순서다. 복원은 전체 대체로 처리하며, 영향 안내와 사용자 확인 전에는 바꾸지 않는다(Q08). 취소·검사 실패·반영 실패는 기존 자료를 유지한다. 복원은 별도 보고서 파일을 생성하지 않는다.

**오류·예외:** 빈 파일·손상·잘못된 형식·지원하지 않는 구조 버전·다른 매장·중복ID·연결 메뉴/재료 누락·단위 오류·필수 기준정보 누락이면 위치와 이유를 알리고 복원을 중단하는 것을 추천한다. 계산 결과 숫자만 담은 파일은 복원할 수 없다. 부분 복원으로 일부 결과만 바뀌지 않게 한다. 백업에 설정되지 않은 최소 수량이 있으면 그것도 미설정 상태로 복원한다. 파일 내용은 실행하지 않고 기록으로만 해석한다.

## 6. 채택한 계산 방법

아래는 9장의 정책에 따라 채택한 1차 계산 방법이다. 프로그램 코드나 세무 회계 기준을 뜻하지 않는다. 실제 결과에는 적용 기간·단위·사용한 기준을 함께 표시한다. 과거 기록에 이미 있는 순매출·수수료·원가 값은 임의로 다시 계산해 덮지 않는다. 기록값과 검산값이 다르면 데이터 문제로 알리고 해결 전까지 어떤 값이 쓰였는지 밝힌다.

### C01. 판매 한 행의 매출

- 할인 전 판매금액 = 판매수량 × 실제 판매단가.
- 순매출 = 할인 전 판매금액 − 해당 행 전체 할인액.
- 할인은 개당이 아니라 행 전체 금액으로 제안한다. 시안의 “할인 총액”과 맞는다.
- 할인액이 판매금액보다 크면 입력 오류로 처리하는 방향이다. 음수 순매출을 0으로 바꾸는 시안 코드를 따르지 않는다.
- 수수료는 실제 금액을 직접 입력하고 순매출과 별도로 보존하고 공헌이익에서 고려한다. 순매출에서 빼고 공헌이익에서 다시 빼는 중복을 피한다.

### C02. 판매에 적용할 개당 원가

**기존 판매:** 기록된 개당 식재료원가·포장원가를 사용한다. 당시 레시피 버전도 보존한다.

**새 판매 추천(Q03):** 판매 날짜 이전 또는 당일에 시작한 가격이력 중 가장 최근 값을 사용한다. 미래 가격을 끌어오지 않는다. 원가 단위가 맞는 각 재료에 대해 다음을 계산한다.

- 재료 기준단위당 가격 = 구매가격 ÷ 구매용량.
- 메뉴 한 개의 해당 재료 비용 = 레시피 개당 사용량 × 기준단위당 가격.
- 개당 식재료원가 = 해당 메뉴·레시피의 식재료 비용 합계.
- 개당 포장원가 = 해당 채널에 적용되는 포장재 비용 합계.
- 현재 제공 자료의 포장재는 I10·I11로 확인한다. 향후 다른 재료를 임의로 포장재 분류에 추가하지 않는다.
- 구매용량이 0/누락이거나 기준단위가 다르면 해당 원가 계산을 중단한다. 가격이력 누락을 최초가격·현재가격으로 조용히 대체하지 않는다.

새 판매 저장 시 이 개당 원가와 적용 레시피를 고정하는 방향을 추천한다. 판매 수정은 Q03의 값 유지·재산정 기준을 따른다. 1차에서는 R1 한 버전만 확인됐으므로 다른 버전의 적용 기간을 만들어내지 않는다.

### C03. 판매 공헌이익과 수수료

- 판매 식재료비 = 수량 × 당시 개당 식재료원가.
- 판매 포장비 = 수량 × 당시 개당 포장원가.
- 판매 변동비 = 판매 식재료비 + 판매 포장비 + 결제수수료 금액.
- 판매 공헌이익 = 순매출 − 판매 변동비.
- 공헌이익률 = 공헌이익 ÷ 순매출 × 100. 순매출이 0이면 비율 계산 불가.
- 수수료는 **A안: 실제 금액 직접 입력**을 추천한다(Q02). 요율을 선택한 B안이라면 “순매출 × 합의한 요율”로 계산한다. 3%를 기본값으로 정하지 않는다.

설명 예시: 2025-07-01 가격이력의 원두 1,000g에 23,000원, 우유 1,000ml에 2,900원과 라떼 R1의 원두 20g·우유 200ml를 쓰면 개당 식재료원가는 1,040원이다. **가상의 신규 입력**으로 매장 라떼 10개를 개당 4,800원, 할인 0원, 수수료 직접 입력 720원으로 기록하면 순매출 48,000원, 식재료비 10,400원, 포장비 0원, 공헌이익 36,880원이다. 720원은 이 설명을 위한 입력값이며 기본 수수료나 실제 새 판매가 아니다.

### C04. 메뉴·채널 합계

- 메뉴·채널별 수량/순매출/식재료비/포장비/수수료/공헌이익은 선택 기간의 해당 기록 합계.
- 그룹 공헌이익률 = 그룹 공헌이익 합계 ÷ 그룹 순매출 합계 × 100.
- 전체 공헌이익률도 전체 금액 합계로 구한다. 각 행 비율의 단순 평균을 쓰지 않는다.
- 같은 메뉴의 매장+포장 합계와 채널별 행은 서로 다른 표시 수준이다. 전체 합계에 두 수준을 함께 더하지 않는다.
- 완료된 기간의 판매가 없는 메뉴와 미완료 기간의 미입력 메뉴를 구분한다.

### C05. 실제 기간 손익

- 총 순매출 = 대상 판매들의 순매출 합계.
- 총 판매 변동비 = 대상 판매들의 식재료비 + 포장비 + 수수료 합계.
- 운영비 = 같은 기간에 귀속된 비용기록 금액 합계.
- 기본 손익 제안 = 총 순매출 − 총 판매 변동비 − 운영비 = 공헌이익 합계 − 운영비.
- 월비용계획을 운영비에 한 번 더 더하지 않는다. 재료 입고 구매대금을 판매 식재료비와 함께 자동 비용 처리하지 않는다.
- 비용 8개 항목을 모두 고정비라고 설명하지 않는다. 제공된 비용은 날짜별 귀속 기록으로 그대로 사용하고 새로운 일별 배분식을 자동 적용하지 않는 방향을 추천한다(Q10).
- 폐기·실사 차이의 금액은 1차 손익에 추가하지 않는다(Q11). 1차 추천은 기본식을 사용하고 “판매·운영비 기준 손익, 재고 손실 별도 미반영”처럼 한계를 표시하는 방식이다. 재고 수량에는 폐기·실측을 반영한다.
- 이 손익을 통장 현금 잔액이나 세무 신고용 확정 영업이익으로 설명하지 않는다.

### C06. 대시보드 비율과 건수

- 원가율 = 해당 판매 변동비 ÷ 순매출 × 100. 손익률 = 해당 손익 ÷ 순매출 × 100.
- 매장/포장 비중을 제공할 때는 **순매출 금액 비중** 추천. 판매수량 비중과 섞지 않는다. 분모 0이면 계산 불가.
- 판매 기록 건수는 실제 집계행 수, 비용 기록 건수는 비용행 수다. 메뉴수·주문수·비용항목수와 구분한다.
- 목록 필터가 있는 요약은 필터된 전체 결과를 기준으로 한다. 대시보드는 선택 기간 전체 결과다. 필터가 다르면 숫자가 다를 수 있음을 명시한다.
- 금액 내부 정밀도를 유지하고 화면에서 원 단위, 비율 소수 한 자리로 보여주는 방향을 추천한다. 반올림 시점·자릿수는 Q04의 채택 기준을 따른다. 표시한 행과 총계가 반올림으로 다르면 그 이유를 알린다.

### C07. 판매 재료 사용량

- 재료 사용량 = 판매수량 × 해당 레시피의 개당 재료 사용량.
- 적용채널이 비어 있으면 모든 채널, 포장이면 포장 판매에만 적용.
- 서로 다른 재료의 g·ml·개를 합치지 않는다.
- 위 라떼 10개 예시의 사용량은 원두 200g, 우유 2,000ml다. 포장으로 변경하면 해당 레시피에 따라 포장컵 10개도 포함한다.
- 기존 기록은 당시 레시피 버전으로, 새 기록은 Q03에서 선택한 기준으로 연결한다. 레시피 없음을 사용량 0으로 바꾸지 않는다.

### C08. 장부 잔량과 실측

실측이 없는 구간의 기본식은 다음과 같다.

**기준일 잔량 = 초기재고 + 누적입고 − 누적판매사용 − 누적폐기 + 적용할 실사조정량.**

실측이 있는 경우 추천은 “실측값을 새 출발점으로 삼는 방식”이다(Q05).

1. 기준일 이전의 마지막 실측이 없으면 초기재고부터 계산한다.
2. 마지막 실측이 있으면 해당 실측수량을 기준으로 이후 입고·판매사용·폐기·실측 없는 조정 기록을 반영한다.
3. 새 실사 차이 = 실제 센 수량 − 실사 직전 장부 잔량. 실제 센 수량과 차이를 모두 저장하되 효과를 두 번 적용하지 않는다.
4. 제공 자료에 이미 들어 있는 실사조정은 실측을 함께 가진 같은 기록이다. 실측 기준으로 잔량을 잡고 그 기록의 조정량까지 다시 더하지 않는다.
5. 실측이 없는 조정량은 구간 내 증감으로 한 번 적용한다. 실측수량 0도 유효한 실측으로 인식한다.

예: 실사 직전 우유 4,200ml, 실제 4,000ml이면 차이는 −200ml이고 그 시점 잔량은 4,000ml다. 4,000ml에서 다시 200ml를 빼 3,800ml로 만들지 않는다.

소급 판매 수정 제안: 실사 이전 판매를 고치면 실사 직전 계산값과 설명상 차이를 다시 확인하되, 실제로 센 수량은 유지한다. 그 실사 이후 잔량을 무조건 판매 차이만큼 늘리거나 줄이지 않는다. 실사 이후 판매 수정은 이후 잔량에 반영한다. 원자료의 과거 조정량 보존과 재계산 차이 표시를 구분하는 상세 정책은 Q05의 채택 기준을 따른다.

### C09. 재고 유형과 날짜 내 순서

- 입고 증감 = 입력한 입고량. 폐기 증감 = −입력한 폐기량.
- 실사조정 증감 = 실측량 − 실사 직전 장부 잔량.
- 자료에 시각이 없으므로 당일 입고·판매사용·폐기를 반영하고 영업 종료 실사를 마지막에 적용하는 방향을 추천한다(Q05). 등록 순서만으로 과거 판매의 효과를 결정하지 않는다.
- 같은 날 같은 재료의 여러 실사를 자동 선택하지 않는다. 1차는 한 날짜·한 재료의 실측을 한 번으로 제한한다(Q05).
- 미래 변동을 현재 잔량에 미리 반영하지 않는다. 월 조회여도 기준일까지의 과거 누적 자료가 필요하다.

### C10. 부족 판정

- 기준 없음: 판정 보류. 잔량 계산 불가: 판정 불가.
- 잔량 < 최소 수량: 부족. 잔량 ≥ 최소 수량: 기준 충족.
- 부족량 = 최소 수량 − 잔량, 부족한 경우에만 표시.
- 예: 최소 5,000ml와 잔량 4,200ml면 800ml 부족. 이 5,000ml는 설명용 시안 값이지 실제 운영 기준값이 아니다.
- 부족량은 최소 기준까지의 차이이며 구매 묶음 단위의 권장 발주량이 아니다. 공급사 발주·납기·안전재고 일수는 2차에서 다룬다.

## 7. 공통 오류 대응과 상태

| 상황 | 제안 동작 | 결과·자료 보존 |
| --- | --- | --- |
| 입력 오류 | 어떤 칸이 왜 잘못됐는지 표시하고 저장하지 않는다. 예: “할인 총액은 판매금액보다 클 수 없습니다.” | 입력을 유지, 기존 기록·집계 불변 |

| 정상 조회 결과 없음 | 조건에 맞는 기록이 없다고 안내한다. | 미마감·완료 후 0·검색 불일치를 구분 |

삭제 확인과 복원 확인은 기존 자료에 큰 영향을 주므로 추천한다. 메시지 문구·표시 위치는 화면 설계에서 다듬으며 실제 정책 선택을 대신하지 않는다.

1차에는 아래 계산이나 파일을 제공하지 않는다. FRD만 읽어도 전체 제품의 향후 기능을 알 수 있도록 목표와 필요한 결정을 남긴다.

| PRD의 2차 기능 | 사용자 행동 → 향후 처리·결과 | 계산·오류·결정할 내용 |
| --- | --- | --- |
| 예상 손익 | 전망 기간 선택 → 실제 완료 실적과 미래 예상 구간을 구분한 예상 손익 | 예상 순매출 − 예상 판매 관련 비용 − 예상 운영비 방향 제안. 기간·판매 가정·원가·비용 전제 미정. 근거 부족이면 전망 불가로 표시. |

| 주·분기·반기·연간 조회 | 기간 선택 → 해당 기간 실적과 기준일 재고 | 주 시작일·사업연도 미정. 부분 연도·미완료 기간을 전체 실적으로 설명하지 않음. |

| 월 비용계획 편집·비교 | 월별 계획 입력·수정 → 실제 비용과 비교 | 전체 월 계획과 완료 일부 기간의 실적을 공정하게 비교할 기준 미정. 실적 비용에 계획을 추가하지 않음. |
| 기준정보·가격·레시피 관리 | 신규 메뉴·재료 및 변경 등록 → 새 판매에 적용 | 적용 시작일·버전·기존 기록 보존·참조 중인 항목 삭제 제한을 설계해야 함. |
| 재고 기록 수정·삭제·분석 | 과거 변동 선택 → 관련 잔량·실사 구간 재검토 | 수정 순서·실측 기준 보호·손익 영향 미정. 1차에는 일반 수정/삭제를 추가하지 않음. |
| 반품·취소와 판매 일괄 처리 | 기존 판매 선택 또는 대상 기록 지정 → 취소·반품 등 합의한 유형에 따라 판매와 관련 결과 변경 | 취소와 실제 반품을 구분하고 재료를 다시 사용할 수 있는지, 할인·수수료를 돌려받는지 확인 필요. 판매수량을 음수로 입력하거나 재료를 자동 복구하는 규칙을 임의로 정하지 않음. 잘못된 대상·이미 취소된 기록·처리 일부 실패 대응은 2차 설계 사항. |
| 수익성 분류·상세 비교 | 합의한 기준 선택 → 분류·기간 비교 | 좋음/개선 필요의 기준값과 근거 미정. 시안의 “건전 수익”을 자동 채택하지 않음. |
| 자동 백업·여러 기기·추가 매장 자료 | 운영 범위 확장 → 자료 공유·보존 방식 확장 | 충돌·사용자·매장 구분·백업 주기·저장처를 재기획해야 함. |

발주서 작성, 판매 내역 엑셀 내보내기, 재고 내역 파일 내보내기, 클라우드 백업, POS/배달 연동, 전일 동시간 비교, 실사 주기 권고는 **미승인 추가 기능**이다. 시안에 있어도 개발 요구사항에 추가하지 않는다. 나중에 포함하려면 별도 사용자 확인이 필요하다.

## 9. 추천 기준으로 마무리한 1차 정책

2026-10-12 사용자의 “추천대로 하고 완료해줘” 지시에 따라 기존 추천을 채택하고 필요한 세부 기준을 정리했다. PRD의 제품 범위를 늘리지 않는다. 다음은 1차 구현의 기준이며, 앞장의 추천 설명은 이 표의 구체적인 기준에 따라 적용한다. 실제 재료별 최소 수량은 운영자가 정하는 값이므로 만들어 넣지 않는다.

| 번호 | 확정한 작동 기준 | 이유와 예시 |
| --- | --- | --- |
| Q01 | PRD에 없는 추가 버튼은 1차 작동 화면에서 숨긴다. 필수 기능의 누락된 입력·복원 화면만 보완한다. | 발주서·내역 내보내기·클라우드 등을 추가하지 않고 혼동을 줄인다. 시안 원본 파일은 변경하지 않았다. |
| Q02 | 새 판매 수수료는 실제 금액 직접 입력. 빈칸은 오류이고 실제 0원은 허용한다. | 실제 수수료 720원을 입력하며, 예시 3%를 기본 요율로 쓰지 않는다. |

### 운영 값과 2차 사항

추가 선택 질문은 종료한다. 실제 재료별 최소 수량은 프로그램에서 운영자가 입력할 값으로 남는다. 기준을 입력하지 않아도 기록·잔량 확인은 가능하고 부족 판정만 보류한다. 주 시작일·사업연도, 전망 기간·방법, 엑셀 열 구성·가져오기 충돌 처리 등은 2차 착수 때 정한다. 저장 위치·파일 형식·배포 방식은 별도 TRD에 정리한다.

## 11. 문서 완료와 구현 조건

1차 기능·버튼·입력·계산·화면/파일 결과·오류 대응과 추천 기준의 정리를 완료했다. PRD의 4시간 목표와 1차 필수 기능을 유지한다. 구현 방식은 [03_TRD.md](03_TRD.md)에 정리한다. 2차와 미승인 추가 기능은 1차에 넣지 않는다.

실제 재료별 최소 수량은 개발을 막는 미결 정책이 아니라 운영자가 입력할 값이다. 미설정 상태의 판정 보류를 구현한다. 개발 중 자료 구조나 저장 환경의 제약이 발견되면 원본 보호와 핵심 흐름을 우선하고 영향을 알린다. 이번 작업은 문서 완료이며 프로그램 코드·화면 수정·검사 통과·배포 완료를 뜻하지 않는다.
