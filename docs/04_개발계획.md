# 카페 판매·손익·재고 관리 1차 개발계획

- 작성일: 2026-10-12
- 상태: 개발계획은 사용자 확인으로 확정됐다. EPIC 1은 U01~U12 사용자 확인까지 통과해 2026-10-12 완료다. EPIC 2는 구현·자체 검사를 통과했고 사용자 확인 대기다. EPIC 3은 미착수다.
- 근거: [PRD](01_PRD.md), [FRD](02_FRD.md), [TRD](03_TRD.md), design 폴더의 시안.

## 전체 작업 순서와 나눈 이유

**판매·메뉴 수익성 → 비용·손익·백업 → 재고 운영·복원** 순서로 진행한다. 총 **3개 EPIC, 15개 Story**다.

EPIC은 함께 완성할 작업 묶음이고, Story는 사용자가 한 가지 목적을 달성하는 기능이다. 15개 미만도 검토했지만, 수정·삭제와 백업·복원을 각각 나누어 확인할 수 있도록 15개로 구성했다. 저장과 검사는 각 Story에 포함한다.

| 순서 | EPIC | Story 수 | 끝나면 화면에서 확인할 결과 |
| --- | --- | ---: | --- |
| 1 | 판매와 메뉴 수익성 | 5 | 판매를 관리하고 마감된 메뉴 수익성을 확인 |
| 2 | 비용과 매장 손익 | 5 | 비용을 관리하고 실제 손익과 백업 파일을 확인 |
| 3 | 재고 운영과 자료 복원 | 5 | 입고·폐기·실측·부족 재료를 확인하고 자료 복원 |

기준정보·계산·저장이 먼저 있어야 판매가 작동하고, 판매 결과와 비용이 있어야 손익을 확인할 수 있다. 재고는 판매 사용량에 연결하며, 복원은 모든 기록과 설정을 다룰 수 있게 된 마지막 단계에서 검증한다.

## 모든 Story의 공통 완료 조건

- 실제 기록으로 계산하고 실제로 저장한다. 시안의 고정 숫자나 성공 문구만으로 완료 처리하지 않는다.
- 입력 검사와 계산 검산, 저장 후 재접속 검사를 포함한다.
- 저장 실패·취소 시 기존 자료를 보호한다. 연속 클릭과 재시도로 중복 반영되지 않아야 한다.
- 미입력·실제 0·미마감·계산 불가를 구분한다.
- 자동 검사는 입력 오류를 막는 검사와 개발자가 반복 실행하는 계산·저장 시험을 뜻한다.

## EPIC 1. 판매와 메뉴 수익성

**개발 순서:** 1.1 → 1.2 → 1.3 → 1.4 → 1.5

기준정보 반영, 공통 계산과 저장은 1.1의 내부 작업으로 시작한다.

### Story 1.1 — 기존 자료의 메뉴 수익성 확인

- **사용자가 할 수 있는 일:** 일·월을 선택해 메뉴별 판매량, 순매출, 재료·포장·수수료와 메뉴가 남긴 금액을 확인한다.
- **자동 검사:** 최초 자료 중복 반영 방지, 메뉴·재료 연결, 당시 원가 보존, 합계와 비율 검산, 매출 0과 원가 누락 처리.
- **화면 확인 행동과 예상 결과:** 2026년 9월을 선택한다. 완료 실적은 18일까지로 표시되고 19~30일을 매출 0으로 채우지 않는다. 전체 메뉴를 확인할 수 있고, 다시 열어도 기록 수가 늘지 않는다.

### Story 1.2 — 판매 기록 추가

- **사용자가 할 수 있는 일:** 날짜·메뉴·채널·수량·단가·할인·실제 수수료를 입력하고 저장한다.
- **자동 검사:** 날짜·수량·금액, 과다 할인, 중복 집계, 가격·레시피 누락, 원가와 사용량 계산, 저장 전 재고 차감 방지.
- **화면 확인 행동과 예상 결과:** 새 판매를 입력하면 계산 미리보기가 바뀐다. 저장하면 목록에 나타나고 재접속 후에도 남는다. 미마감 판매는 잠정으로 표시되며 완료 실적에는 아직 포함되지 않는다.

### Story 1.3 — 판매 기록 수정

- **사용자가 할 수 있는 일:** 잘못된 판매 내용만 고친다.
- **자동 검사:** 기록ID 유지, 변경 전 효과 제거, 날짜·메뉴·채널 변경 시 원가 재산정, 수량만 변경 시 당시 개당 원가 유지, 다른 행과의 중복 차단.
- **화면 확인 행동과 예상 결과:** 매장 판매를 포장으로 바꾸면 포장 원가와 재료 사용량이 달라진다. 수량을 고치면 결과가 한 번만 변경되고, 해당 날짜는 다시 마감해야 하는 상태가 된다.

### Story 1.4 — 판매 기록 삭제

- **사용자가 할 수 있는 일:** 잘못 등록한 판매를 확인 후 삭제한다.
- **자동 검사:** 해당 판매의 집계 효과만 제거, 반복 삭제 방지, 저장 실패 시 원기록 유지, 비용·실측 기록 보존.
- **화면 확인 행동과 예상 결과:** 삭제 취소 시 그대로 남고, 확인하면 목록에서 사라진다. 재접속 후에도 삭제 상태이며 관련 결과가 맞는다.

### Story 1.5 — 하루 기록 마감

- **사용자가 할 수 있는 일:** 해당 날짜의 기록을 끝냈다고 표시한다.
- **자동 검사:** 미래 날짜·필수 기록 오류의 마감 차단, 중복 마감 방지, 판매 0 확인, 변경된 날짜의 재마감 처리.
- **화면 확인 행동과 예상 결과:** 잠정 판매가 있는 날짜를 마감하면 완료 실적에 포함된다. 이후 판매를 수정하면 미완료로 돌아가고, 다시 마감하면 수정된 결과로 반영된다.

**EPIC 완료 기준:** 판매 추가·수정·삭제 → 마감 → 메뉴 수익성 확인이 실제 화면에서 연결된다. 재료 사용량 계산도 자동 검사로 확인하고, 기록은 재접속 후 보존된다.

## EPIC 2. 비용과 매장 손익

**선행 조건:** EPIC 1의 저장·기간 조회·마감·판매 계산

**개발 순서:** 2.1 → 2.2 → 2.3 → 2.4 → 2.5

### Story 2.1 — 비용 기록 추가

- **사용자가 할 수 있는 일:** 비용이 해당되는 날짜, 기존 비용항목, 금액을 입력한다.
- **자동 검사:** 필수값·음수 금액·날짜 검사, 실제 0원 허용, 비용ID 중복 방지, 월비용계획 자동 변경 방지.
- **화면 확인 행동과 예상 결과:** 비용을 저장하면 목록에 나타나고 재접속 후에도 남는다. 해당 날짜는 미완료로 표시되며 월계획은 바뀌지 않는다.

### Story 2.2 — 비용 기록 수정

- **사용자가 할 수 있는 일:** 잘못된 비용 날짜·항목·금액을 고친다.
- **자동 검사:** 기록ID 유지, 날짜 이동 시 이전·새 날짜 반영, 다른 비용과 월계획 보존, 실패 시 기존 기록 유지.
- **화면 확인 행동과 예상 결과:** 금액을 변경하면 해당 기록만 바뀐다. 날짜를 옮기면 이전·새 날짜 모두 재마감 대상으로 표시된다.

### Story 2.3 — 비용 기록 삭제

- **사용자가 할 수 있는 일:** 잘못 등록한 비용을 확인 후 삭제한다.
- **자동 검사:** 지정한 비용만 제거, 중복 삭제 방지, 취소·저장 실패 시 보존, 판매·재고 영향 없음.
- **화면 확인 행동과 예상 결과:** 삭제 확인 후 목록에서 사라진다. 같은 날짜·항목의 다른 비용과 판매 기록은 남는다.

### Story 2.4 — 실제 기간 손익 확인

- **사용자가 할 수 있는 일:** 일·월별 매출, 판매 관련 비용, 운영비와 손익을 확인한다.
- **자동 검사:** 메뉴 공헌이익 합계와 손익 연결, 월계획 중복 차감 방지, 완료·잠정 구분, 적자·매출 0·누락 자료 처리, 반올림 검산.
- **화면 확인 행동과 예상 결과:** 비용을 변경하고 재마감하면 운영비와 손익이 바뀐다. 메뉴 공헌이익은 그대로이며, 적자는 음수로 표시된다. 재고 손실 금액이 별도 미반영이라는 설명을 확인할 수 있다.

### Story 2.5 — 현재 자료 백업

- **사용자가 할 수 있는 일:** 마지막으로 저장한 자료를 JSON 백업 파일로 내려받는다.
- **자동 검사:** 기준정보·판매·비용·재고·달력·최소 기준 포함, 미저장 입력 제외, 형식·버전·건수 검사, 파일 생성 실패 처리.
- **화면 확인 행동과 예상 결과:** 백업을 누르면 파일 내려받기가 시작된다. 저장 전 입력은 포함되지 않았다는 안내가 나오며, 파일에는 결과 숫자만이 아니라 원기록과 설정이 들어 있다.

**EPIC 완료 기준:** 판매와 비용을 마감한 뒤 실제 손익을 확인할 수 있다. 비용 변경·삭제가 손익에 정확히 반영되고, 복원에 필요한 내용이 들어 있는 백업 파일을 만들 수 있다.

## EPIC 3. 재고 운영과 자료 복원

**선행 조건:** 기존 재고·판매 사용량 계산, 공통 저장, 백업 형식

**개발 순서:** 3.1 → 3.2 → 3.3 → 3.4 → 3.5

### Story 3.1 — 재료 입고 기록

- **사용자가 할 수 있는 일:** 날짜·재료·입고량·사유를 기록한다.
- **자동 검사:** 기존 재료·단위·수량·날짜 검사, 잔량 증가, 반복 클릭 중복 방지, 취소·저장 실패 처리.
- **화면 확인 행동과 예상 결과:** 우유 입고를 저장하면 해당 기준일 이후 잔량이 입고량만큼 증가한다. 저장 전에는 기존 잔량이 바뀌지 않는다.

### Story 3.2 — 재료 폐기 기록

- **사용자가 할 수 있는 일:** 버린 재료의 양과 사유를 기록한다.
- **자동 검사:** 양수 입력을 감소량으로 보존, 중복 차감 방지, 음수 잔량 경고, 손익에 폐기 금액 자동 추가하지 않음.
- **화면 확인 행동과 예상 결과:** 폐기를 저장하면 잔량이 감소한다. 음수가 되면 실제 수량과 경고를 보여주며 0으로 바꾸지 않는다.

### Story 3.3 — 실제 센 재고 기록

- **사용자가 할 수 있는 일:** 재료를 실제로 센 수량을 기록해 새 재고 기준으로 삼는다.
- **자동 검사:** 실측 0 허용, 날짜·재료별 중복 실측 방지, 실측과 조정량 중복 반영 방지, 실측 전 판매 수정 영향 검산.
- **화면 확인 행동과 예상 결과:** 장부 4,200ml에서 실제 4,000ml를 기록하면 차이는 −200ml, 실측 기준은 4,000ml다. 3,800ml로 이중 차감되지 않고 재접속 후에도 유지된다.

### Story 3.4 — 잔량과 부족한 재료 확인

- **사용자가 할 수 있는 일:** 기준일 잔량을 조회하고 기존 재료의 최소 수량을 설정해 부족 여부를 확인한다.
- **자동 검사:** 초기재고·판매·입고·폐기·실측 연결, 단위·소수 자릿수 검사, 미설정과 0 구분, 기준과 같은 잔량은 충족 처리, 검색·부족 필터 일치.
- **화면 확인 행동과 예상 결과:** 최소 기준이 없으면 판정 보류로 보인다. 기준을 설정하면 부족 여부가 바뀌지만 실재고는 바뀌지 않는다. 부족 재료만 보기에서 해당 재료만 나타난다.

### Story 3.5 — 백업으로 전체 자료 복원

- **사용자가 할 수 있는 일:** 백업 파일을 선택하고 현재 자료를 대체해 복원한다.
- **자동 검사:** 형식·버전·매장·ID·참조·단위·건수 검사, 전체 대체의 일괄 저장, 실패·취소 시 기존 자료 보호, 복원 전후 기록·계산 일치.
- **화면 확인 행동과 예상 결과:** 백업 후 판매·비용·재고·최소 기준을 변경한다. 원래 백업을 복원하면 이전 기록과 결과로 돌아간다. 손상 파일이나 취소는 현재 자료를 바꾸지 않는다.

**EPIC 완료 기준:** 판매 사용량·입고·폐기·실측이 잔량에 연결되고 부족 판정이 정확하다. 모든 종류의 기록과 설정을 백업·복원한 뒤 재접속해도 결과가 일치한다.

기존 문서의 4시간 목표에 맞춘 예산이다. 최종 확인에서는 **판매 입력 → 마감 → 메뉴 수익성 → 손익 → 재료 잔량 → 백업·복원**을 실제 화면에서 끝까지 실행한다. 계산·저장·오류 검사가 실패하면 완료로 처리하지 않는다.

엑셀 양식·가져오기, 예상 손익, 권장 발주량과 추가 기간 조회는 2차로 유지한다.
